# sysdvr-lite

<p align="center"><a href="README.md">English</a> &nbsp;|&nbsp; <b>Русский</b></p>

Маленький клиент [SysDVR](https://github.com/exelix11/SysDVR) на C с минимумом зависимостей. Сделан для Orange Pi Zero 2W (Allwinner H618, arm64 Linux), которой официальный клиент на .NET не по силам.

Он принимает видео и звук Nintendo Switch по **USB** и выводит их на HDMI-дисплей без X11 и Wayland. На целевой плате (Orange Pi Zero 2W, Allwinner H618) 720p30 декодируется **аппаратным декодером H.264**, а картинка выводится через **GPU**; клиент занимает около 5–8% одного ядра процессора.

> Сторона Switch (сисмодуль SysDVR) **не изменяется**. Установите на консоль обычный релиз SysDVR и используйте эту программу вместо официального клиента.

## Зачем

Официальный клиент — приложение на .NET с интерфейсом ImGui/SDL. На Orange Pi Zero 2W у него получался только слайд-шоу в 720p30, даже с программным декодером, из-за накладных расходов среды выполнения и конвертации. Этот клиент держит весь конвейер на C и использует аппаратный декодер платы.

## Возможности

- Протокол SysDVR 02 и 03 по USB (libusb), с горячим подключением и автоматическим переподключением.
- Сменные видеодекодеры:
  - `v4l2`: родное декодирование H.264 через stateless V4L2 для VPU **Cedrus** от Allwinner (H616/H618, ядро mainline). ffmpeg не используется. Есть собственный разборщик SPS/PPS/заголовков слайсов.
  - `ffmpeg`: программный запасной вариант через libavcodec (или любой декодер libavcodec по имени), с настройками малой задержки.
  - `null`: отбрасывает данные, для проверки сети и протокола.
- Вывод без оконной системы: KMS/DRM с режимом дисплея, подобранным под видео, без масштабирования. Кадры импортируются как dmabuf в EGL/GLES и конвертируются в RGB на GPU сразу в буфер вывода. Если GPU-стека нет, переключается на конвертацию на процессоре.
- Звук через ALSA (48 кГц, стерео, S16) с синхронизацией звука и видео: оба потока несут метки времени консоли, звук подстраивается под картинку. Видео никогда не задерживается.
- Экран консоли выключается, пока клиент подключён, и включается обратно при отключении (это делает сисмодуль SysDVR по запросу клиента, протокол 03). Отключается опцией `--keep-screen`.
- Если консоль отключить, дисплей возвращается в терминал (никакого застывшего последнего кадра), а при повторном подключении картинка появляется снова.
- После загрузки на текстовой консоли написано по-английски и по-русски, что всё запущено и можно подключать Switch (`--no-banner` отключает). Сторожевой таймер перезапускает клиент, если он завис, а не только если упал.
- Переживает сбои дисплея и звука: если ТВ выключили или переткнули HDMI, картинка возвращается сама, программа ждёт дисплей, которого ещё нет, а звуковой выход открывается заново, когда становится доступен (например, если HDMI-звук не был готов при загрузке).
- Если консоль три секунды не присылает видео (игра ушла с экрана: меню HOME, окно выбора контроллеров, системное окно), вместо замершей картинки на дисплее рисуется сообщение на русском с английской копией под ним. С патченным системным модулем из [switch-module](switch-module/README.ru.md) экран консоли при этом включается сам (и снова гаснет, когда игра вернулась); с обычным SysDVR он остаётся выключенным, и в сообщении сказано нажать кнопку питания консоли два раза (сон и пробуждение). Картинка возвращается сама, когда возвращается игра. `--no-notice` отключает сообщение.
- Вписывает картинку в дисплеи без режима 1280x720 (`--scale fit`, по умолчанию; `--scale none` центрирует 1:1).
- Очереди с малой задержкой: если декодер не успевает, старые пакеты отбрасываются, и декодирование продолжается со следующего ключевого кадра.
- Только arm64 Linux (на другой платформе сборка не настроится).

## Состояние

Проверено на Orange Pi Zero 2W с Armbian (Debian 13, ядро 6.18) и настоящей Switch (SysDVR 6.3, протокол 03) по USB: 720p30, без потерянных кадров, горячее подключение работает, вывод аппаратного декодера побитово совпадает с libavcodec на тестовых потоках. Полный путь (чистый образ Armbian, `install.sh`, перезагрузка, автозапуск, картинка и звук) проверен на чистой системе, а `update.sh` — на уже установленной.

### Измерения

Orange Pi Zero 2W, аппаратный декодер (`v4l2`), вывод 1280x720@60, Switch Lite по USB, поток 720p30, почти статичная сцена, релиз 1.2.0 (замер от 2026-11-02). Задержка измерена через `SYSDVR_LATENCY=1`, 9 окон по 150 кадров.

| Что | В среднем | В худшем случае |
|---|---|---|
| Ожидание в очереди | 0,05 мс | 0,09 мс |
| Пакет получен по USB до декодированного кадра (Cedrus) | 3,3 мс | 7,5 мс |
| Конвертация на GPU и переключение кадра (`show()`) | 3,4 мс | 4,0 мс |
| **Пакет получен до кадра на экране (по vblank)** | **16,6-17,5 мс** | **26-27 мс** |

Около 10 мс из этого итога занимает ожидание следующего обновления дисплея на 60 Гц, так что сама обработка занимает порядка 7 мс. Это только часть платы: собственная задержка захвата и кодирования на консоли и задержка самого дисплея сюда не входят, а полная цепочка от нажатия кнопки до экрана не измерялась. Звук идёт в среднем примерно на 20 мс позже картинки.

| Нагрузка при стриме | Значение |
|---|---|
| Все 4 ядра | занято 1,6 % |
| Процесс `sysdvr-lite` | около 7 % одного ядра |
| Load average (1 / 5 / 15 мин) | 0,36 / 0,34 / 0,21 |
| Память процесса | 87 МБ |
| Температура SoC (без радиатора) | 56,6 C |

Декодирование и конвертация цвета идут на VPU и GPU, поэтому процессор почти не занят (во время замера его частота была 480 МГц). Сцена с большим количеством движения отдельно не измерялась.

Ограничения декодера: только прогрессивное видео, без B-кадров, без MMCO и долгосрочных опорных кадров, без матриц масштабирования, без FMO. На практике это не ограничение: кодировщик консоли всегда выдаёт один и тот же поток (профиль High, уровень 3.2, один опорный кадр, POC тип 2, CABAC, один слайс на кадр, IDR каждые 30 кадров), поэтому сисмодуль SysDVR и клиенты зашивают его SPS/PPS в код. `SYSDVR_H264_INFO=1` печатает параметры увиденного потока. Если появится что-то неподдерживаемое, в лог будет записана явная ошибка.

Не проверено: другие платы Allwinner (варианты H616 должны работать, но не тестировались), режимы 1080p, отличные от вывода 1280x720 (картинка центрируется, но не масштабируется).

## Сравнение с аналогами (для Switch Lite)

У Switch Lite нет видеовыхода, поэтому HDMI-карта захвата с ней не работает вообще (док-станции тоже нет). Остаются программная передача по порту USB-C или по сети и неофициальный аппаратный мод. Факты ниже взяты со страниц самих проектов (проверено 2026-11-02); где числа нет, его нет и здесь. Задержки разных проектов измерены по-разному и напрямую сравнивать их нельзя: 17 мс выше это только часть платы, а Switch Frame Tap приводит свою цифру «от и до». Все программные варианты требуют консоль с кастомной прошивкой (Atmosphere) и несут обычный для неё риск; только аппаратный мод обходится без неё. Цены те, что я нашёл, они могли измениться.

|  | Нужен ПК | Меню HOME / системные экраны | Видео | Задержка (по документации) | Звук | Что нужно на консоли | Цена | Удобство |
|---|---|---|---|---|---|---|---|---|
| **sysdvr-lite** (этот проект) | Нет: картинка идёт на HDMI-дисплей | Только игра; с патченным модулем экран консоли возвращается в меню HOME | 720p30 | часть платы около 17 мс, в худшем 27 мс (задержка самой консоли не входит) | Да, по HDMI | Кастомная прошивка Atmosphere и системный модуль SysDVR в режиме USB (патченный по желанию) | ПО бесплатно; покупать нужно только плату: Orange Pi Zero 2W стоила около 13-27 USD при выходе в 2023 (1-4 ГБ), плюс карта, блок питания и кабели; проверьте, что плату ещё продают | Плата с образом: ставится одной командой, потом вставил консоль и играешь; стартует при включении, ничего запускать не надо |

| [Switch Frame Tap](https://github.com/TomasUribe/switch-frame-tap) | Да (ПК или Android) | Да, меню HOME, системные экраны и оверлеи тоже, но только как бета по включению, там без звука, оверлеи чуть менее плавные | до 1080p60 (с доп. средствами) | около 45 мс (720p) - 60 мс (1080p), от и до ПК без монитора | Да, только игра | Atmosphere, экспериментальный модуль, проверен на нескольких консолях | ПО бесплатно, но нужен ПК или Android-устройство; если его нет, это стоит заметно дороже платы | Доп. средства для 1080p и драйвер USB в Windows; экспериментальный |

Чем этот проект отличается: это готовая коробка без ПК, ставится одной командой, стартует при включении и не трогает железо консоли. Чего он не делает: поток фиксирован консолью на 720p30, задержка выше, чем у аппаратного мода (тот отдаёт картинку сразу на HDMI, без кодирования и без передачи по USB, с ним не сравнится ни одно программное решение), а меню HOME не захватывается (рисуется сообщение, а с необязательным модулем экран консоли возвращается). Если нужен HOME и вы готовы вскрыть консоль, лучше подойдёт аппаратный мод; если нужен поток только на ПК, проще всего официальный клиент SysDVR.

## Требования

- **Orange Pi Zero 2W** с **Armbian** (на базе Debian; проверенный образ: Debian 13 «trixie» minimal/server с ядром `current`). Хватит карты на 8 ГБ, установленная система занимает около 2–3 ГБ.
- Nintendo Switch с обычным сисмодулем [SysDVR](https://github.com/exelix11/SysDVR) в режиме **USB** и USB-кабель к порту платы, который работает в режиме хоста.
- HDMI-дисплей (телевизор или монитор с режимом 1280x720).
- Доступ в интернет на плате на время установки. Часы настраивать вручную не нужно: на плате нет батарейки для часов, и `install.sh` сам включает сетевое время, если часы не синхронизированы (иначе `apt` выдаёт «Release file is not valid yet»).

## Первая загрузка чистого образа Armbian

Пропустите этот раздел, если на плате уже стоит Armbian и она в сети.

1. Загрузите плату с только что записанной карты и войдите как `root` (на консоли или по SSH). При первом входе система попросит задать пароль для `root`.
2. Если после этого она предложит создать нового пользователя, можно нажать `Ctrl+C`, пропустить это и продолжать работать от `root`.
3. Подключите плату к сети: запустите `armbian-config`, выберите **Network**, затем **BNS001 (Basic network setup)**. Выберите **Wi-Fi** (у Orange Pi Zero 2W нет порта Ethernet, поэтому обычно это Wi-Fi) или проводное подключение, затем свою сеть, введите её пароль и везде, где попросит, подтверждайте кнопкой **OK**. Названия пунктов меню в разных версиях Armbian могут немного отличаться.
4. Убедитесь, что интернет есть, например `ping -c 3 github.com`, и переходите к установке ниже.

## Быстрая установка (только Orange Pi Zero 2W)

> **Скрипт установки поддерживает только Orange Pi Zero 2W с Armbian (на базе Debian).** На любой другой плате или дистрибутиве он отказывается работать. Сам клиент собирается только под arm64 Linux.

Одна команда, ничего скачивать заранее не нужно (скрипт спросит подтверждение; чтобы пропустить вопрос, добавьте после `bash` строку `-s -- --yes`):

```bash
curl -fsSL https://raw.githubusercontent.com/VLPLAY-Games/sysdvr-lite/main/install.sh | sudo bash
```

Скрипт клонирует репозиторий в `/opt/sysdvr-lite` (меняется опцией `--dir`). Можно и клонировать самому и запустить из этой копии:

```bash
git clone https://github.com/VLPLAY-Games/sysdvr-lite
cd sysdvr-lite
sudo ./install.sh
```

Во время установки плате нужен интернет. Скрипт:

1. проверяет, что работает на Orange Pi Zero 2W с Armbian/Debian,
2. включает сетевое время, если часы не синхронизированы, и дожидается синхронизации,
3. устанавливает git, если его нет, и клонирует репозиторий (пропускается, если запущен из копии репозитория),
4. устанавливает через `apt` все пакеты для сборки и работы из `packages.txt`,
5. задаёт пул CMA 128 МБ в `/boot/armbianEnv.txt` (резервная копия сохраняется рядом, пропустить можно опцией `--no-cma`),
6. собирает клиент и устанавливает его в `/usr/local/bin`,
7. создаёт и включает systemd-сервис `sysdvr-lite`, чтобы он запускался при загрузке и ждал Switch.

Если размер CMA изменился, скрипт попросит перезагрузиться (`sudo reboot`). После этого сервис запускается сам при каждой загрузке: при включённом режиме USB в SysDVR на консоли достаточно подключить её, и картинка появится на HDMI-дисплее, клавиатура не нужна. Если отключить консоль, дисплей вернётся в терминал, а при повторном подключении картинка вернётся.

Проверка установки:

```bash
systemctl is-active sysdvr-lite                 # active
grep Cma /proc/meminfo                          # CmaTotal: 131072 kB
journalctl -u sysdvr-lite -n 20 --no-pager      # cedrus / Mali-G31 / GPU conversion enabled
```

Опции: `--audio-device NAME` (по умолчанию `plughw:CARD=HDMI,DEV=0`, список через `aplay -L`), `--decoder v4l2|ffmpeg` (по умолчанию `v4l2`), `--dir PATH` (куда клонировать при запуске через curl, по умолчанию `/opt/sysdvr-lite`), `--stock-sysdvr` (на консоли обычный SysDVR: без окна с сообщением, как в 1.0), `--no-cma`, `--video-mode WxH[@HZ]` (заставить ядро использовать этот режим с самой загрузки, `off` убирает; см. «Если что-то не работает»), `--binary` (поставить готовый бинарник из последнего релиза вместо сборки: без компилятора и пакетов для разработки, только Debian 13; доступно с релиза 1.1.0), `--force` (попробовать другую плату arm64 или систему на базе Debian: мной не проверялось, расскажите, как получилось), `--yes` (без запроса подтверждения, обязательна, если нет терминала). При запуске через curl опции указываются после `bash -s --`, например `... | sudo bash -s -- --yes --decoder ffmpeg`.

## По желанию: экран консоли в паузах (патченный системный модуль)

SysDVR гасит экран консоли на время стрима и включает его обратно только когда клиент отключился. Когда игра уходит с экрана (меню HOME, окно выбора контроллеров, системное окно), консоль ничего не присылает, экран остаётся выключенным, и чтобы увидеть, что от вас хотят, нужно два раза нажать кнопку питания. [switch-module](switch-module/README.ru.md) — это системный модуль SysDVR (только USB) с одним небольшим дополнением: экран сам включается через несколько секунд без видео и снова гаснет, когда игра вернулась. К каждому релизу приложены два файла:

- `exefs.nsp`: заменить одноимённый файл в `SD:/atmosphere/contents/00FF0000A53BB665/`, если SysDVR на консоли уже стоит;
- `SysDVR-USB-screenwatch.zip`: для консоли, где SysDVR ещё нет, распаковать в корень SD-карты.

Это необязательно: с обычным SysDVR всё работает как раньше, а `install.sh --stock-sysdvr` ставит клиент без окна с сообщением.

## Обновление

На плате, в папке репозитория (`/opt/sysdvr-lite`, если ставили через curl):

```bash
sudo /opt/sysdvr-lite/update.sh
```

Скрипт забирает свежий код, проверяет, что все пакеты из `packages.txt` всё ещё установлены (недостающие доустанавливает, например если вы их удалили или новой версии нужно больше), пересобирает, устанавливает новый бинарник и перезапускает сервис. Настройка CMA и параметры сервиса (декодер, аудиоустройство) не затрагиваются. Опция `./update.sh --no-pull` пересобирает локальную копию, ничего не скачивая. Плата, установленная с `--binary`, получает готовый бинарник последнего релиза вместо сборки (`./update.sh --build` принудительно собирает из исходников).

## Изменение настроек

Сервис читает опции из `/etc/default/sysdvr-lite`, одна строка:

```
SYSDVR_OPTS="--decoder v4l2 --drm --audio-device plughw:CARD=HDMI,DEV=0"
```

Отредактируйте её (например, смените аудиоустройство, список устройств в `aplay -L`) и перезапустите сервис:

```bash
sudo nano /etc/default/sysdvr-lite
sudo systemctl restart sysdvr-lite
```

Повторный запуск установщика с `--audio-device` или `--decoder` тоже перезапишет этот файл. `update.sh` его не трогает (плата, установленная до появления файла, получит его при первом обновлении из старого unit-файла). Сам unit-файл править не нужно: `update.sh` заменяет его версией из репозитория. Все опции командной строки перечислены в разделе [Использование](#использование).

## Защита SD-карты при внезапном отключении питания

Плату рассчитано выдёргивать из розетки без выключения. Armbian уже помогает: корневая система ext4 с журналом, логи (`/var/log`) и `/tmp` лежат в памяти, а сам клиент на карту ничего не пишет. Отключение питания во время редкой записи (обновление, смена настройки) всё же может повредить карту, а износ карты никак не предотвратить.

Для самой сильной защиты `sudo /opt/sysdvr-lite/tools/readonly-root.sh enable` и перезагрузка делают корневую систему только для чтения (overlayroot): всё, что пишется во время работы, идёт в память и пропадает при следующей загрузке, так что карта вообще не записывается. Цена: **ничего из изменённого не переживёт перезагрузку** (настройки в `/etc/default/sysdvr-lite`, новый пароль Wi-Fi, пакеты, обновления). Чтобы что-то изменить, выполните `readonly-root.sh disable`, перезагрузитесь, измените, выполните `enable` и перезагрузитесь снова; `install.sh` и `update.sh` не запускаются, пока режим включён. `readonly-root.sh status` показывает состояние. Если плата не загружается после `enable`, вставьте карту в компьютер и добавьте `overlayroot=disabled` в строку `extraargs=` файла `/boot/armbianEnv.txt` на первом разделе. Это необязательно и по умолчанию выключено. **На настоящей плате он ещё не проверялся** (проверены только синтаксис и логика скрипта), поэтому сначала попробуйте на запасной карте.

## Удаление

```bash
sudo systemctl disable --now sysdvr-lite
sudo rm /etc/systemd/system/sysdvr-lite.service /usr/local/bin/sysdvr-lite
sudo systemctl daemon-reload
```

Чтобы отменить изменение CMA, восстановите резервную копию, которую сделал установщик: `sudo cp /boot/armbianEnv.txt.sysdvr-lite.bak /boot/armbianEnv.txt`, и перезагрузитесь. Установленные пакеты остаются на месте.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `apt` пишет «Release file is not valid yet» при установке | Неверные часы. `install.sh` исправляет это сам; если вы видите это из `update.sh`, выполните `sudo timedatectl set-ntp true` и подождите, пока `timedatectl` не покажет `System clock synchronized: yes`. |
| Установщик отказывается запускаться | Он поддерживает только Orange Pi Zero 2W с Armbian/Debian. В сообщении указано, что было обнаружено. |
| Нет картинки, в логе ничего про консоль | `lsusb` должен показывать `18d1:4ee0` (SysDVR). Если нет: SysDVR не в режиме USB, не тот кабель (он должен передавать данные) или не тот USB-порт. |
| Нет картинки, `journalctl -u sysdvr-lite` показывает ошибки | Отсутствие `/dev/video0` значит, что драйвер Cedrus не загружен (попробуйте `--decoder ffmpeg`). Сообщение «decoder keeps failing» перезапускает сервис, пришлите строки лога перед ним. |
| Картинка есть, звука нет | Выберите устройство ALSA через `aplay -L` и задайте его, как описано в разделе [Изменение настроек](#изменение-настроек). Для HDMI это `plughw:CARD=HDMI,DEV=0`. |
| Звук есть, картинки нет, в журнале `not the DRM master` | Экраном владела другая программа (например, второй клиент). Клиент завершается, и systemd сам запускает его заново. Если повторяется, проверьте, что работает один: `pgrep -a sysdvr-lite`. |
| Звук и картинка рассинхронизированы | Попробуйте `--av-offset` (миллисекунды, положительное значение сдвигает звук позже) и `SYSDVR_SYNC=1`, чтобы увидеть измеренное расхождение. |
| Экран консоли остаётся выключенным после отключения | Сисмодуль сам включает его через мгновение после разрыва соединения. Если этого не произошло, заблокируйте и разблокируйте консоль кнопкой питания или запустите клиент с `--keep-screen`, чтобы экран не выключался вовсе. В самом SysDVR эта функция помечена как экспериментальная. |
| Чёрный экран при отключённой консоли | Это терминал; войдите на дисплее или по SSH. Картинка вернётся сама, когда консоль будет подключена. |
| Картинка замерла, на дисплее надпись «Нет изображения от консоли» | Игра не на экране консоли (меню HOME, окно выбора контроллеров, системное окно), и SysDVR ничего не присылает. Вернитесь в игру, и картинка вернётся. Чтобы увидеть экран консоли сейчас, нажмите её кнопку питания два раза (сон и пробуждение), запускайте с `--keep-screen`, чтобы экран не выключался, или поставьте на консоль патченный системный модуль из [switch-module](switch-module/README.ru.md), тогда экран включится сам. |
| Редко 4K-телевизор не показывает картинку (ни загрузочных сообщений, ни терминала), пока не начался стрим, а сам стрим работает | До стрима ядро использует режим, который предпочитает телевизор, и это может быть 4K при 60 Гц. Некоторые телевизоры иногда не поднимают такой канал (замечено один раз на Sony 4K, который в остальных запусках показывал терминал в 4K, то есть виноваты капризы телевизора или кабель, а не клиент). Заставьте ядро использовать 720p, как стрим: переустановите командой `sudo /opt/sysdvr-lite/install.sh --video-mode 1280x720` (или сами добавьте `video=HDMI-A-1:1280x720@60` в строку `extraargs=` файла `/boot/armbianEnv.txt`) и перезагрузитесь; `--video-mode off` возвращает всё обратно. Также может помочь выключить и включить телевизор или другой HDMI-кабель. |
| Высокая загрузка процессора | В логе должно быть `GPU conversion enabled`. Если произошёл откат на конвертацию на CPU, установите пакеты для GPU (см. «Ручная сборка»). |

Ничего не помогло? Запустите на плате `sudo ./tools/doctor.sh > doctor.txt` (он только читает и не включает имя хоста и адреса) и приложите файл к [issue на GitHub](https://github.com/VLPLAY-Games/sysdvr-lite/issues/new/choose). Отчёты о том, как всё работает на других телевизорах, мониторах и платах, тоже приветствуются.

## Советы

- **Стримить на 30 кадрах в секунду.** SysDVR отправляет не больше 30 кадров в секунду, даже если игра работает на 60. Если вы уже пользуетесь ограничителем кадров на консоли (например, FPSLocker), поставьте 30 для игр, которые стримите: это экономит заряд и нагрев и делает движение в стриме ровнее, потому что кадры не выбрасываются. Решать вам: не все игры поддерживают ограничитель, и в некоторых при 30 кадрах чуть больше задержка управления.

## Ручная сборка

Нужны: компилятор C11, CMake, pkg-config. Все библиотеки необязательны, и каждая включает соответствующую возможность, если найдена.

| Возможность | Пакеты Debian/Ubuntu |
|---|---|
| USB-транспорт (обязательно) | `libusb-1.0-0-dev` |
| Программный декодер (запасной) | `libavcodec-dev libavutil-dev` |
| Звук | `libasound2-dev` |
| Вывод DRM/KMS | `libdrm-dev` |
| Конвертация на GPU | `libgbm-dev libegl-dev libgles-dev libgl1-mesa-dri libegl-mesa0` |
| Декодер V4L2 | заголовки ядра (`linux-libc-dev`) |

```bash
sudo apt install build-essential cmake ninja-build pkg-config v4l-utils \
    libusb-1.0-0-dev libavcodec-dev libavutil-dev libasound2-dev \
    libdrm-dev libgbm-dev libegl-dev libgles-dev libgl1-mesa-dri libegl-mesa0
cmake -S . -B build -G Ninja
cmake --build build
```

На этапе настройки CMake печатает, какие возможности включены.

## Использование

```bash
# Switch по USB, аппаратный декодер, вывод на HDMI (именно это запускает сервис)
./build/sysdvr-lite --decoder v4l2 --drm --audio-device plughw:CARD=HDMI,DEV=0
```

Клиент ждёт, пока появится консоль с SysDVR в режиме **USB**, и переподключается после её отключения.

| Опция | Описание |
|---|---|
| `--decoder null\|ffmpeg\|v4l2` | Видеобэкенд, по умолчанию `ffmpeg`. Для аппаратного декодера используйте `v4l2`. |
| `--threads N` | Число потоков программного декодера. |
| `--ffmpeg-name NAME` | Использовать конкретный декодер libavcodec. |
| `--video-device /dev/videoN` | Файл устройства для бэкенда `v4l2`, по умолчанию `/dev/video0`. |
| `--drm[=/dev/dri/cardN]` | Выводить на дисплей через KMS. |
| `--out FILE` | Писать сырые декодированные кадры в файл вместо показа. |
| `--no-audio` / `--no-video` | Отключить поток. |
| `--audio-device NAME` | Устройство ALSA, например `plughw:CARD=HDMI,DEV=0`. |
| `--audio-batching 0..3` | Сколько аудиопакетов консоль накапливает перед отправкой, по умолчанию 1. |
| `--av-offset MS` | Сдвиг звука относительно видео (положительное значение — звук позже). |
| `--scale fit\|none` | Если у дисплея нет режима размера видео: вписать картинку (по умолчанию) или центрировать 1:1. |
| `--no-notice` | Не рисовать сообщение, когда консоль не присылает видео (для консоли с обычным SysDVR, как в версии 1.0). |
| `--keep-screen` | Не выключать экран консоли во время стрима (по умолчанию он выключается). |
| `--test-file FILE.h264` | Воспроизвести файл Annex-B вместо USB (проверка декодера). |
| `--version` | Напечатать версию и возможности этой сборки (ffmpeg, drm, gpu, alsa, v4l2). |

Переменные окружения для отладки: `SYSDVR_NOGL=1` отключает вывод через GPU, `SYSDVR_DUMP=file` сохраняет 60-й кадр буфера вывода как сырой XRGB (в PNG-скриншот его превращает `tools/xrgb2png.py`), `SYSDVR_LATENCY=1` печатает задержку конвейера, `SYSDVR_SYNC=1` печатает расхождение звука и видео, `SYSDVR_H264_INFO=1` печатает свойства потока, `SYSDVR_PKTSTAT=1` раз в секунду печатает, сколько пакетов видео и звука пришло и что выдал декодер, `SYSDVR_PROF=1` печатает время работы пути конвертации на CPU.

### Автозапуск (systemd)

`install.sh` делает это за вас. Вручную:

```bash
sudo cmake --install build --prefix /usr/local
sudo cp tools/sysdvr-lite.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sysdvr-lite
```

Чтобы поменять декодер или аудиоустройство, создайте `/etc/default/sysdvr-lite` со строкой `SYSDVR_OPTS="..."` (см. [Изменение настроек](#изменение-настроек)). Логи: `journalctl -u sysdvr-lite -f`.

## Заметки по Orange Pi Zero 2W

- Проверено с Armbian (current, ядро 6.18). Драйвер `cedrus` из mainline создаёт `/dev/video0` и `/dev/media0`, а у дисплейного движка **нет YUV-плоскостей**, поэтому цветовое преобразование выполняет GPU.
- `install.sh` поднимает CMA до 128 МБ, добавляя `extraargs=cma=128M` в `/boot/armbianEnv.txt` (стандартных 64 МБ для 720p хватает, но запаса почти нет).
- Switch нужно подключать к USB-порту, который работает в режиме хоста. Проверьте через `lsusb` наличие `18d1:4ee0`.
- Аудиоустройство HDMI обычно `plughw:CARD=HDMI,DEV=0`, проверьте через `aplay -L`.
- `tools/probe_board.sh` печатает всё важное о плате (ядро, узлы V4L2, состояние DRM).

## Проверка без консоли

Опция тестового файла проигрывает поток с частотой 30 кадров/с через весь конвейер:

```bash
./build/gen-h264 test.h264 1                         # тестовый поток 720p30, 1 слайс на кадр (4 = несколько слайсов)
./build/ref-decode test.h264 ref.yuv                 # эталон, декодированный libavcodec
./build/sysdvr-lite --decoder v4l2 --test-file test.h264 --out /tmp/hw.nv12
python3 tools/compare_yuv.py ref.yuv /tmp/hw.nv12    # проверяет, что вывод аппаратного декодера побитово совпадает
```

Сначала остановите сервис (`systemctl stop sysdvr-lite`): декодером одновременно может пользоваться только одна программа. Вывод пишите в RAM-диск вроде `/tmp`: SD-карта не справится с 40 МБ/с сырых кадров.
