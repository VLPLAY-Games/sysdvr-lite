# sysdvr-lite

<p align="center"><a href="README.md">English</a> &nbsp;|&nbsp; <b>Русский</b></p>

Маленький клиент [SysDVR](https://github.com/exelix11/SysDVR) на C с минимумом зависимостей. Сделан для Orange Pi Zero 2W (Allwinner H618, arm64 Linux), которой официальный клиент на .NET не по силам.

Он принимает видео и звук Nintendo Switch по **USB** и выводит их на HDMI-дисплей без X11 и Wayland. На целевой плате (Orange Pi Zero 2W, Allwinner H618) 720p30 декодируется **аппаратным декодером H.264**, а картинка выводится через **GPU**; клиент занимает около 5–8% одного ядра процессора.

> Сторона Switch (сисмодуль SysDVR) **не изменяется**. Установите на консоль обычный релиз SysDVR и используйте эту программу вместо официального клиента.

## Зачем

Официальный клиент — приложение на .NET с интерфейсом ImGui/SDL. На Orange Pi Zero 2W у него получался только слайд-шоу в 720p30, даже с программным декодером, из-за накладных расходов среды выполнения и конвертации. Этот клиент держит весь конвейер на C и использует аппаратный декодер платы.

## Возможности

- Протокол SysDVR 02 и 03 по USB (libusb), с горячим подключением и автоматическим переподключением.
- Сменные видеодекодеры:
  - `v4l2`: родное декодирование H.264 через stateless V4L2 для VPU **Cedrus** от Allwinner (H616/H618, ядро mainline). ffmpeg не используется. Есть собственный разборщик SPS/PPS/заголовков слайсов.
  - `ffmpeg`: программный запасной вариант через libavcodec (или любой декодер libavcodec по имени), с настройками малой задержки.
  - `null`: отбрасывает данные, для проверки сети и протокола.
- Вывод без оконной системы: KMS/DRM с режимом дисплея, подобранным под видео, без масштабирования. Кадры импортируются как dmabuf в EGL/GLES и конвертируются в RGB на GPU сразу в буфер вывода. Если GPU-стека нет, переключается на конвертацию на процессоре.
- Звук через ALSA (48 кГц, стерео, S16) с синхронизацией звука и видео: оба потока несут метки времени консоли, звук подстраивается под картинку. Видео никогда не задерживается.
- Экран консоли выключается, пока клиент подключён, и включается обратно при отключении (это делает сисмодуль SysDVR по запросу клиента, протокол 03). Отключается опцией `--keep-screen`.
- Если консоль отключить, дисплей возвращается в терминал (никакого застывшего последнего кадра), а при повторном подключении картинка появляется снова.
- Очереди с малой задержкой: если декодер не успевает, старые пакеты отбрасываются, и декодирование продолжается со следующего ключевого кадра.
- Только arm64 Linux (на другой платформе сборка не настроится).

## Состояние

Проверено на Orange Pi Zero 2W с Armbian (Debian 13, ядро 6.18) и настоящей Switch (SysDVR 6.3, протокол 03) по USB: 720p30, без потерянных кадров, горячее подключение работает, вывод аппаратного декодера побитово совпадает с libavcodec на тестовых потоках. Полный путь (чистый образ Armbian, `install.sh`, перезагрузка, автозапуск, картинка и звук) проверен на чистой системе, а `update.sh` — на уже установленной.

Измерения на этой связке: программная часть конвейера (от приёма пакета по USB до кадра на экране, замер по vblank) занимает в среднем около 14 мс, в худшем случае 25 мс. Собственная задержка захвата и кодирования на консоли сюда не входит. Звук идёт в среднем примерно на 20 мс позже картинки. Опубликованных данных о задержке официальных клиентов SysDVR для сравнения нет.

Ограничения декодера: только прогрессивное видео, без B-кадров, без MMCO и долгосрочных опорных кадров, без матриц масштабирования, без FMO. На практике это не ограничение: кодировщик консоли всегда выдаёт один и тот же поток (профиль High, уровень 3.2, один опорный кадр, POC тип 2, CABAC, один слайс на кадр, IDR каждые 30 кадров), поэтому сисмодуль SysDVR и клиенты зашивают его SPS/PPS в код. `SYSDVR_H264_INFO=1` печатает параметры увиденного потока. Если появится что-то неподдерживаемое, в лог будет записана явная ошибка.

Не проверено: другие платы Allwinner (варианты H616 должны работать, но не тестировались), режимы 1080p, отличные от вывода 1280x720 (картинка центрируется, но не масштабируется).

## Требования

- **Orange Pi Zero 2W** с **Armbian** (на базе Debian; проверенный образ: Debian 13 «trixie» minimal/server с ядром `current`). Хватит карты на 8 ГБ, установленная система занимает около 2–3 ГБ.
- Nintendo Switch с обычным сисмодулем [SysDVR](https://github.com/exelix11/SysDVR) в режиме **USB** и USB-кабель к порту платы, который работает в режиме хоста.
- HDMI-дисплей (телевизор или монитор с режимом 1280x720).
- Доступ в интернет на плате на время установки. Часы настраивать вручную не нужно: на плате нет батарейки для часов, и `install.sh` сам включает сетевое время, если часы не синхронизированы (иначе `apt` выдаёт «Release file is not valid yet»).

## Первая загрузка чистого образа Armbian

Пропустите этот раздел, если на плате уже стоит Armbian и она в сети.

1. Загрузите плату с только что записанной карты и войдите как `root` (на консоли или по SSH). При первом входе система попросит задать пароль для `root`.
2. Если после этого она предложит создать нового пользователя, можно нажать `Ctrl+C`, пропустить это и продолжать работать от `root`.
3. Подключите плату к сети: запустите `armbian-config`, выберите **Network**, затем **BNS001 (Basic network setup)**. Выберите **Wi-Fi** (у Orange Pi Zero 2W нет порта Ethernet, поэтому обычно это Wi-Fi) или проводное подключение, затем свою сеть, введите её пароль и везде, где попросит, подтверждайте кнопкой **OK**. Названия пунктов меню в разных версиях Armbian могут немного отличаться.
4. Убедитесь, что интернет есть, например `ping -c 3 github.com`, и переходите к установке ниже.

## Быстрая установка (только Orange Pi Zero 2W)

> **Скрипт установки поддерживает только Orange Pi Zero 2W с Armbian (на базе Debian).** На любой другой плате или дистрибутиве он отказывается работать. Сам клиент собирается только под arm64 Linux.

Одна команда, ничего скачивать заранее не нужно (скрипт спросит подтверждение; чтобы пропустить вопрос, добавьте после `bash` строку `-s -- --yes`):

```bash
curl -fsSL https://raw.githubusercontent.com/VLPLAY-Games/sysdvr-lite/main/install.sh | sudo bash
```

Скрипт клонирует репозиторий в `/opt/sysdvr-lite` (меняется опцией `--dir`). Можно и клонировать самому и запустить из этой копии:

```bash
git clone https://github.com/VLPLAY-Games/sysdvr-lite
cd sysdvr-lite
sudo ./install.sh
```

Во время установки плате нужен интернет. Скрипт:

1. проверяет, что работает на Orange Pi Zero 2W с Armbian/Debian,
2. включает сетевое время, если часы не синхронизированы, и дожидается синхронизации,
3. устанавливает git, если его нет, и клонирует репозиторий (пропускается, если запущен из копии репозитория),
4. устанавливает через `apt` все пакеты для сборки и работы из `packages.txt`,
5. задаёт пул CMA 128 МБ в `/boot/armbianEnv.txt` (резервная копия сохраняется рядом, пропустить можно опцией `--no-cma`),
6. собирает клиент и устанавливает его в `/usr/local/bin`,
7. создаёт и включает systemd-сервис `sysdvr-lite`, чтобы он запускался при загрузке и ждал Switch.

Если размер CMA изменился, скрипт попросит перезагрузиться (`sudo reboot`). После этого сервис запускается сам при каждой загрузке: при включённом режиме USB в SysDVR на консоли достаточно подключить её, и картинка появится на HDMI-дисплее, клавиатура не нужна. Если отключить консоль, дисплей вернётся в терминал, а при повторном подключении картинка вернётся.

Проверка установки:

```bash
systemctl is-active sysdvr-lite                 # active
grep Cma /proc/meminfo                          # CmaTotal: 131072 kB
journalctl -u sysdvr-lite -n 20 --no-pager      # cedrus / Mali-G31 / GPU conversion enabled
```

Опции: `--audio-device NAME` (по умолчанию `plughw:CARD=HDMI,DEV=0`, список через `aplay -L`), `--decoder v4l2|ffmpeg` (по умолчанию `v4l2`), `--dir PATH` (куда клонировать при запуске через curl, по умолчанию `/opt/sysdvr-lite`), `--no-cma`, `--yes` (без запроса подтверждения, обязательна, если нет терминала). При запуске через curl опции указываются после `bash -s --`, например `... | sudo bash -s -- --yes --decoder ffmpeg`.

## Обновление

На плате, в папке репозитория (`/opt/sysdvr-lite`, если ставили через curl):

```bash
sudo /opt/sysdvr-lite/update.sh
```

Скрипт забирает свежий код, проверяет, что все пакеты из `packages.txt` всё ещё установлены (недостающие доустанавливает, например если вы их удалили или новой версии нужно больше), пересобирает, устанавливает новый бинарник и перезапускает сервис. Настройка CMA и параметры сервиса (декодер, аудиоустройство) не затрагиваются. Опция `./update.sh --no-pull` пересобирает локальную копию, ничего не скачивая.

## Изменение настроек

Сервис запускает `sysdvr-lite` с параметрами из своего unit-файла. Чтобы сменить аудиоустройство или декодер, можно заново запустить установщик с нужными опциями (он сохраняет вашу настройку CMA и переписывает unit; он снова запускает `apt`, поэтому нужен интернет):

```bash
sudo ./install.sh --yes --audio-device plughw:CARD=Codec,DEV=0 --decoder v4l2
```

или отредактировать `ExecStart` в `/etc/systemd/system/sysdvr-lite.service` и применить:

```bash
sudo systemctl daemon-reload && sudo systemctl restart sysdvr-lite
```

`update.sh` эти параметры никогда не меняет. Все опции командной строки перечислены в разделе [Использование](#использование).

## Удаление

```bash
sudo systemctl disable --now sysdvr-lite
sudo rm /etc/systemd/system/sysdvr-lite.service /usr/local/bin/sysdvr-lite
sudo systemctl daemon-reload
```

Чтобы отменить изменение CMA, восстановите резервную копию, которую сделал установщик: `sudo cp /boot/armbianEnv.txt.sysdvr-lite.bak /boot/armbianEnv.txt`, и перезагрузитесь. Установленные пакеты остаются на месте.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `apt` пишет «Release file is not valid yet» при установке | Неверные часы. `install.sh` исправляет это сам; если вы видите это из `update.sh`, выполните `sudo timedatectl set-ntp true` и подождите, пока `timedatectl` не покажет `System clock synchronized: yes`. |
| Установщик отказывается запускаться | Он поддерживает только Orange Pi Zero 2W с Armbian/Debian. В сообщении указано, что было обнаружено. |
| Нет картинки, в логе ничего про консоль | `lsusb` должен показывать `18d1:4ee0` (SysDVR). Если нет: SysDVR не в режиме USB, не тот кабель (он должен передавать данные) или не тот USB-порт. |
| Нет картинки, `journalctl -u sysdvr-lite` показывает ошибки | Отсутствие `/dev/video0` значит, что драйвер Cedrus не загружен (попробуйте `--decoder ffmpeg`). Сообщение «decoder keeps failing» перезапускает сервис, пришлите строки лога перед ним. |
| Картинка есть, звука нет | Выберите устройство ALSA через `aplay -L` и задайте его, как описано в разделе [Изменение настроек](#изменение-настроек). Для HDMI это `plughw:CARD=HDMI,DEV=0`. |
| Звук и картинка рассинхронизированы | Попробуйте `--av-offset` (миллисекунды, положительное значение сдвигает звук позже) и `SYSDVR_SYNC=1`, чтобы увидеть измеренное расхождение. |
| Экран консоли остаётся выключенным после отключения | Сисмодуль сам включает его через мгновение после разрыва соединения. Если этого не произошло, заблокируйте и разблокируйте консоль кнопкой питания или запустите клиент с `--keep-screen`, чтобы экран не выключался вовсе. В самом SysDVR эта функция помечена как экспериментальная. |
| Чёрный экран при отключённой консоли | Это терминал; войдите на дисплее или по SSH. Картинка вернётся сама, когда консоль будет подключена. |
| Высокая загрузка процессора | В логе должно быть `GPU conversion enabled`. Если произошёл откат на конвертацию на CPU, установите пакеты для GPU (см. «Ручная сборка»). |

## Ручная сборка

Нужны: компилятор C11, CMake, pkg-config. Все библиотеки необязательны, и каждая включает соответствующую возможность, если найдена.

| Возможность | Пакеты Debian/Ubuntu |
|---|---|
| USB-транспорт (обязательно) | `libusb-1.0-0-dev` |
| Программный декодер (запасной) | `libavcodec-dev libavutil-dev` |
| Звук | `libasound2-dev` |
| Вывод DRM/KMS | `libdrm-dev` |
| Конвертация на GPU | `libgbm-dev libegl-dev libgles-dev libgl1-mesa-dri libegl-mesa0` |
| Декодер V4L2 | заголовки ядра (`linux-libc-dev`) |

```bash
sudo apt install build-essential cmake ninja-build pkg-config v4l-utils \
    libusb-1.0-0-dev libavcodec-dev libavutil-dev libasound2-dev \
    libdrm-dev libgbm-dev libegl-dev libgles-dev libgl1-mesa-dri libegl-mesa0
cmake -S . -B build -G Ninja
cmake --build build
```

На этапе настройки CMake печатает, какие возможности включены.

## Использование

```bash
# Switch по USB, аппаратный декодер, вывод на HDMI (именно это запускает сервис)
./build/sysdvr-lite --decoder v4l2 --drm --audio-device plughw:CARD=HDMI,DEV=0
```

Клиент ждёт, пока появится консоль с SysDVR в режиме **USB**, и переподключается после её отключения.

| Опция | Описание |
|---|---|
| `--decoder null\|ffmpeg\|v4l2` | Видеобэкенд, по умолчанию `ffmpeg`. Для аппаратного декодера используйте `v4l2`. |
| `--threads N` | Число потоков программного декодера. |
| `--ffmpeg-name NAME` | Использовать конкретный декодер libavcodec. |
| `--video-device /dev/videoN` | Файл устройства для бэкенда `v4l2`, по умолчанию `/dev/video0`. |
| `--drm[=/dev/dri/cardN]` | Выводить на дисплей через KMS. |
| `--out FILE` | Писать сырые декодированные кадры в файл вместо показа. |
| `--no-audio` / `--no-video` | Отключить поток. |
| `--audio-device NAME` | Устройство ALSA, например `plughw:CARD=HDMI,DEV=0`. |
| `--audio-batching 0..3` | Сколько аудиопакетов консоль накапливает перед отправкой, по умолчанию 1. |
| `--av-offset MS` | Сдвиг звука относительно видео (положительное значение — звук позже). |
| `--keep-screen` | Не выключать экран консоли во время стрима (по умолчанию он выключается). |
| `--test-file FILE.h264` | Воспроизвести файл Annex-B вместо USB (проверка декодера). |

Переменные окружения для отладки: `SYSDVR_NOGL=1` отключает вывод через GPU, `SYSDVR_DUMP=file` сохраняет 60-й кадр буфера вывода как сырой XRGB (в PNG-скриншот его превращает `tools/xrgb2png.py`), `SYSDVR_LATENCY=1` печатает задержку конвейера, `SYSDVR_SYNC=1` печатает расхождение звука и видео, `SYSDVR_H264_INFO=1` печатает свойства потока, `SYSDVR_PROF=1` печатает время работы пути конвертации на CPU.

### Автозапуск (systemd)

`install.sh` делает это за вас. Вручную:

```bash
sudo cmake --install build --prefix /usr/local
sudo cp tools/sysdvr-lite.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sysdvr-lite
```

Чтобы поменять декодер или аудиоустройство, отредактируйте строку `ExecStart`. Логи: `journalctl -u sysdvr-lite -f`.

## Заметки по Orange Pi Zero 2W

- Проверено с Armbian (current, ядро 6.18). Драйвер `cedrus` из mainline создаёт `/dev/video0` и `/dev/media0`, а у дисплейного движка **нет YUV-плоскостей**, поэтому цветовое преобразование выполняет GPU.
- `install.sh` поднимает CMA до 128 МБ, добавляя `extraargs=cma=128M` в `/boot/armbianEnv.txt` (стандартных 64 МБ для 720p хватает, но запаса почти нет).
- Switch нужно подключать к USB-порту, который работает в режиме хоста. Проверьте через `lsusb` наличие `18d1:4ee0`.
- Аудиоустройство HDMI обычно `plughw:CARD=HDMI,DEV=0`, проверьте через `aplay -L`.
- `tools/probe_board.sh` печатает всё важное о плате (ядро, узлы V4L2, состояние DRM).

## Проверка без консоли

Опция тестового файла проигрывает поток с частотой 30 кадров/с через весь конвейер:

```bash
./build/gen-h264 test.h264 1                         # тестовый поток 720p30, 1 слайс на кадр (4 = несколько слайсов)
./build/ref-decode test.h264 ref.yuv                 # эталон, декодированный libavcodec
./build/sysdvr-lite --decoder v4l2 --test-file test.h264 --out /tmp/hw.nv12
python3 tools/compare_yuv.py ref.yuv /tmp/hw.nv12    # проверяет, что вывод аппаратного декодера побитово совпадает
```

Сначала остановите сервис (`systemctl stop sysdvr-lite`): декодером одновременно может пользоваться только одна программа. Вывод пишите в RAM-диск вроде `/tmp`: SD-карта не справится с 40 МБ/с сырых кадров.

## Структура

```
src/proto.*          формат пакетов, построение запроса рукопожатия
src/transport_*.c    USB-транспорт и воспроизведение тестового файла
src/queue.*          очередь пакетов с отбрасыванием старых
src/decoder_*.c      декодеры: null / ffmpeg / родной V4L2 (Cedrus)
src/h264_parse.*     разбор SPS, PPS и заголовков слайсов для декодера V4L2
src/sink_*.c         выводы: null, файл и DRM/KMS (+EGL)
src/audio_alsa.c     воспроизведение звука через ALSA
install.sh           установщик для Orange Pi Zero 2W (Armbian), запускается и через curl
update.sh            обновление: pull, доустановка пакетов, пересборка и перезапуск сервиса
packages.txt         пакеты apt, которые используют оба скрипта
tools/               генератор потока, эталонный декодер, скрипт сравнения, проба платы, файл сервиса
docs/DESIGN.md       архитектура и заметки по железу (на английском)
README.md            этот файл на английском
```
